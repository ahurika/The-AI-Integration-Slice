# Documentation Skill

## Purpose

Keep documentation synchronized with the working product.

## Trigger

Use after changes affecting:

* Features
* Architecture
* Database
* Environment
* Authentication
* Setup
* Testing
* Deployment

## Workflow

```text
Implementation
 ↓
Identify Documentation Impact
 ↓
Update Relevant Document
 ↓
Verify Documentation
```

## Document Mapping

| Change                | Update             |
| --------------------- | ------------------ |
| Product requirement   | `PRD.md`           |
| Architecture          | `ARCHITECTURE.md`  |
| Setup/environment     | `DOCUMENTATION.md` |
| Developer orientation | `README.md`        |

## Rule

Documentation must describe the system as it actually exists, not as the agent wishes it existed.
