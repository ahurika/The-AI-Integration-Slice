# Product Requirements Rules

**Priority:** HIGH

## Rules

Every feature must map to an approved requirement.

Before implementation:

1. Identify the relevant PRD requirement.
2. Identify the intended user flow.
3. Identify acceptance criteria.
4. Identify edge cases.
5. Identify security implications.

Do not add functionality because it appears useful.

Do not silently expand scope.

If implementation conflicts with the PRD, stop and resolve the conflict before proceeding.

## Completion

A feature is not complete merely because the interface exists.

The required behaviour, validation, error handling, security, persistence, testing, and documentation must also be addressed where applicable.
