# Documentation Rules

**Priority:** MEDIUM

Documentation must remain synchronized with implementation.

## Update documentation when changing:

* Architecture
* Database schema
* Environment variables
* Authentication behaviour
* Setup
* Testing
* Deployment
* Troubleshooting

## Responsibilities

### PRD.md

Defines what and why.

### ARCHITECTURE.md

Defines technical structure.

### DOCUMENTATION.md

Defines setup, usage, testing, and maintenance.

### README.md

Provides project orientation.

## Accuracy

Never document functionality that does not exist.

Never leave obsolete commands or setup instructions in documentation.
